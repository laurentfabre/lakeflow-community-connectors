01 / Inspect and import

Use the dataset's physical fields

In a Databricks notebook with the updated connector installed, run this metadata inspection using your existing connection. Substitute the dataset ID and connection name:

from databricks.labs.community_connector import register
from databricks.labs.community_connector.sources.crm_analytics.crm_analytics_setup import run_diagnostics

register(spark, "crm_analytics")
spark.conf.set("spark.databricks.unityCatalog.connectionDfOptionInjection.enabled", "true")
report = run_diagnostics(
    spark,
    connection_name="crm-analytics",
    action="inspect",
    dataset_id="<15-or-18-character-dataset-id>",
)

import json
print(json.dumps(report, indent=2))

Save the JSON result as a local .json file and import it below. Inspection reads metadata, without extracting dataset rows. Metadata alone cannot prove scalar values, full visibility, or unique business keys.

03 / Configure the destination

Choose an approved visibility scope

Choose a stable identifier for the approved integration identity and row-visibility contract. A scope change requires a new baseline decision.

Version skipping uses the repository's workspace pipeline. New versions still require full extraction. It requires the updated framework and reader plus expected_snapshot_fingerprint in the connection allowlist.

Key validation storage

Generated row keys use a counter without retaining a key set. SQLite limits the business-key index page cache; it does not bound the entire process or remove API limits. Temporary key storage contains source key values and is cleaned when the read completes, fails, or is closed.
